Performance Budget: planetary.cycle_per_actor
  Per-Actor Cost (P95):  4500ms
  Per-Actor Cost (P99):  6000ms
  
  Why per-actor? Planetary ticks execute SERIALLY (not in parallel)
  
  Scaling to 100 actors:
  
    100 actors × 4500ms (P95) = 450,000ms = 450 seconds = 7.5 MINUTES
    100 actors × 6000ms (P99) = 600,000ms = 600 seconds = 10 MINUTES
    
  Auto-tick interval: 300 seconds (5 minutes)
  
  ⚠️  ALERT: At P95, cycle time (450s) > interval (300s)
              → Tick pile-up: "Previous planetary tick still running, skipping"
  
  ✅ Status: Safe only at < 67 actors (67 × 4500 = 301s ≈ 300s)
  🔴 Status: Risk at 100+ actors without mitigation

Source: src/monkey_brain/kernel/fix/performance_budgets.py:152-164

For 100-Actor Operations (Immediate):

  ✅ Individual request latency is excellent (P99 <200ms)
  ✅ Memory usage is efficient (10.24MB)
  ⚠️  Monitor planetary cycles for tick pile-up
  ⚠️  If "skipping" messages appear in logs, reduce actor count

Option A: Parallelization (Recommended)
  Current: for actor in actors: await tick(actor)  # 450s for 100 actors
  Change: await asyncio.gather(*[tick(actor) for actor in actors])  # 4.5s
  Impact: Enables 100+ actors without tick pile-up
  File: src/monkey_brain/kernel/geography/runtime.py

Option B: Reduce Actor Count
  Safe limit: 67 actors (67 × 4.5s ≈ 300s)
  Requires: No code changes
  Impact: Immediate reduction in tick pile-up risk

Option C: Increase Tick Interval
  Current: 300 seconds (5 minutes)
  Change: 600 seconds (10 minutes)
  Impact: Handles P99 scenarios without pile-up
  Tradeoff: Agents respond slower to state changes

Option D: Reduce Per-Actor Cost
  Strategies:
  - Cache LLM outputs for similar states
  - Use quantized/smaller models
  - Parallelize inference calls
  - Reduce agent planning complexity
  Impact: Enables more actors without cycle extension

  ✅ Individual request latency (P99 < 200ms per tick)
  ✅ Memory efficiency (10.24MB total)
  ✅ Single planetary ticks (completes in <1-2 seconds)

100 concurrent actors present CHALLENGES for:
  ⚠️  Sustained operation with continuous cycles (450s > 300s interval)
  ⚠️  Risk of tick pile-up if P95 costs don't improve

MITIGATION: Parallelize per-actor execution or reduce actor count to <67
            (with current serial implementation).
