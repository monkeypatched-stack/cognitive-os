# Plan: Stage Takt Time/Efficiency Routing Fix

## Status: ✅ COMPLETED

## Problem
Stage attribute queries (takt_time, efficiency, status) were returning line data (e.g., takt_time: 2.4) instead of stage data (e.g., takt_time: 5400).

## Root Cause
The bandit override in `apply_bandit_override()` was changing the classifier's correct "stage" intent to "line" via pattern-key cache in Redis. The classifier correctly returned `pipeline_id="stage"` with 0.67 confidence, but the bandit overrode it before pipeline lookup.

## Fix Applied
Added regex hard-override (confidence=1.0) in `_apply_regex_overrides()` at `goal_router.py` for stage+takt_time/efficiency/status/workstation queries:

```python
# Stage attribute questions — always stage pipeline (hard override, confidence=1.0 prevents bandit)
if re.search(r"\bstage\b", question_lower) and re.search(
    r"\b(?:takt|tackt|tact|efficiency|status|workstations?|line\s+id|belong)\b", question_lower
):
    return "stage", 1.0
```

This sets `goal.metadata["regex_hard_override"] = True` which prevents bandit from overriding.
